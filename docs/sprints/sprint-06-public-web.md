# Спринт 06. Public Web

## Цель

Реализовать публичный Next.js сайт портфолио, который получает данные из backend API и корректно отображает их для посетителей и поисковых систем.

После спринта пользователь должен иметь возможность открыть главную страницу, списки проектов и детальную страницу проекта.

## Контекст

Публичный сайт является витриной проекта. Он должен выглядеть аккуратно, быть адаптивным, быстро загружаться и иметь SEO metadata.

## Задачи

### Общий layout

- Создать общий layout.
- Добавить header с навигацией:
  - "О себе";
  - "Проекты с ИИ";
  - "Другие проекты".
- Добавить footer с текстом `2026`.
- Сделать активные/понятные состояния ссылок, если это вписывается в дизайн.

### API client

- Создать `lib/api.ts`.
- Настроить base URL backend API через env.
- Добавить функции:
  - получить page content;
  - получить список проектов;
  - получить проект по slug.
- Обработать ошибки backend API.

### Типы

- Создать `lib/types.ts`.
- Описать:
  - `PageContent`;
  - `Project`;
  - `ProjectCategory`.

### Страница "О себе"

- Реализовать маршрут `/`.
- Получать `GET /api/pages/about`.
- Рендерить `htmlContent`.
- Добавить SEO metadata:
  - title;
  - description.
- Обработать состояние отсутствия контента.

### Страница "Проекты с ИИ"

- Реализовать маршрут `/ai-projects`.
- Получать `GET /api/projects?category=AI`.
- Отображать карточки проектов.
- При отсутствии проектов показать аккуратное пустое состояние.
- Добавить SEO metadata.

### Страница "Другие проекты"

- Реализовать маршрут `/other-projects`.
- Получать `GET /api/projects?category=OTHER`.
- Использовать ту же карточку проекта.
- Добавить SEO metadata.

### Страница проекта

- Реализовать маршрут `/projects/[slug]`.
- Получать `GET /api/projects/{slug}`.
- Для 404 от backend показывать Next.js not found.
- Отображать:
  - title;
  - image;
  - shortDescription;
  - htmlContent;
  - category.
- Генерировать SEO metadata из данных проекта.

### Компоненты

- Создать `Header`.
- Создать `Footer`.
- Создать `ProjectCard`.
- Для `ProjectCard`:
  - изображение слева, если `imageUrl` задан;
  - fallback-состояние без изображения, если `imageUrl` пустой;
  - название жирным;
  - краткое описание;
  - вся карточка кликабельна;
  - адаптивное поведение на mobile.

### Адаптивность

- Проверить desktop.
- Проверить tablet.
- Проверить mobile.
- Убедиться, что длинные названия и описания не ломают карточки.

## Результат спринта

- Публичный сайт работает с backend API.
- Все публичные маршруты из ТЗ реализованы.
- SEO metadata задана для основных страниц и проектов.
- Списки проектов и страницы проекта отображают реальные данные.

## Definition of Done

- `/` отображает HTML страницы `about`.
- `/ai-projects` показывает опубликованные AI-проекты.
- `/other-projects` показывает опубликованные OTHER-проекты.
- `/projects/[slug]` показывает опубликованный проект.
- Неопубликованный или отсутствующий проект дает 404.
- Страницы адаптивны.
- Сборка Next.js проходит без ошибок.

## Риски и решения

- HTML из backend нужно рендерить осторожно. Если sanitizer не добавлен на backend, это нужно отметить как security debt.
- Next.js metadata может потребовать повторного запроса данных. Нужно избежать лишней сложности, но сохранить корректное SEO.
- Изображения SeaweedFS могут потребовать настройки allowed image domains или использования обычного `img`, если `next/image` неудобен для локального S3 URL.

## Что не входит в спринт

- Административная панель.
- Авторизация на frontend.
- Редактирование контента.
- Docker production routing.
