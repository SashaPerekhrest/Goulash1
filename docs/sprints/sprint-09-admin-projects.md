# Спринт 09. Admin Projects

## Цель

Реализовать управление проектами в административной панели: списки, создание, редактирование, удаление, публикация и загрузка изображения.

После спринта админка должна стать полноценной мини-CMS для двух разделов проектов: `AI` и `OTHER`.

## Контекст

Backend Projects API и Files API уже должны быть готовы. В админке есть авторизация, layout, API-клиент и TinyMCE.

## Задачи

### Общий подход

- Сделать общий feature-модуль проектов.
- Переиспользовать одну таблицу и одну форму для категорий `AI` и `OTHER`.
- Категорию определять маршрутом:
  - `/admin/ai-projects` -> `AI`;
  - `/admin/other-projects` -> `OTHER`.

### Таблица проектов

- Отображать список проектов категории.
- Колонки:
  - title;
  - shortDescription;
  - publication status;
  - actions.
- Действия:
  - edit;
  - delete.
- Добавить кнопку "Создать".
- Показывать loading state.
- Показывать empty state.
- Показывать error state.

### Модальное окно проекта

- Открывать modal для создания и редактирования.
- Ширина modal около 90% экрана.
- Поля формы:
  - title;
  - slug;
  - imageUrl / upload image, необязательное поле;
  - shortDescription;
  - htmlContent через TinyMCE;
  - isPublished.
- Для категории использовать контекст страницы, а не ручной выбор, если это проще и безопаснее.

### Create flow

- Администратор нажимает "Создать".
- Открывается пустая форма.
- При необходимости загружает изображение через `POST /api/admin/files`.
- После upload `imageUrl` подставляется в форму.
- Форма отправляется на `POST /api/admin/projects`.
- После успеха modal закрывается, список обновляется.

### Edit flow

- Администратор нажимает "Редактировать".
- Загружается проект или используется объект из списка, если в нем достаточно данных.
- Форма открывается с текущими значениями.
- При сохранении отправляется `PUT /api/admin/projects/{id}`.
- После успеха список обновляется.

### Delete flow

- Администратор нажимает "Удалить".
- Показать confirmation dialog.
- При подтверждении отправить `DELETE /api/admin/projects/{id}`.
- После успеха список обновляется.

### Upload image

- Добавить file input.
- Разрешить типы, соответствующие backend:
  - jpeg;
  - png;
  - webp;
  - svg.
- Показывать состояние загрузки.
- Показывать ошибку загрузки.
- После успешной загрузки отображать preview изображения, если есть URL.

### Валидация формы

- Проверить обязательные поля:
  - title;
  - slug;
  - shortDescription;
  - htmlContent.
- Проверить формат slug.
- Проверить максимальные длины.
- Отображать ошибки backend validation.

## Результат спринта

- Администратор может управлять AI-проектами.
- Администратор может управлять OTHER-проектами.
- Изображения загружаются в SeaweedFS через backend.
- Публичный сайт автоматически отображает опубликованные проекты.

## Definition of Done

- `/admin/ai-projects` показывает AI-проекты.
- `/admin/other-projects` показывает OTHER-проекты.
- Создание проекта работает.
- Редактирование проекта работает.
- Удаление проекта работает с подтверждением.
- Загрузка изображения работает и сохраняет URL.
- Переключение `isPublished` влияет на публичный сайт.
- Ошибки API отображаются пользователю.

## Риски и решения

- Большая форма с TinyMCE внутри modal может быть тяжелой. Нужно проверить UX и высоту modal.
- Если использовать один компонент формы для обеих категорий, важно не дать случайно сохранить проект не в ту категорию.
- При конфликте slug нужно показать понятную ошибку около поля slug или в форме.

## Что не входит в спринт

- Bulk actions.
- Drag-and-drop сортировка проектов.
- Удаление файлов из SeaweedFS.
- История изменений.
- Preview проекта перед публикацией.
