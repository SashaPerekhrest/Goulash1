# Спринт 02. Auth и защищенная зона API

## Цель

Реализовать авторизацию администратора и защитить административные endpoints через JWT Bearer.

После спринта backend должен уметь принимать логин и пароль, возвращать access token и проверять этот токен на защищенных маршрутах.

## Контекст

Административная панель управляет HTML-контентом и проектами, поэтому все admin API должны быть закрыты. Публичные endpoints остаются доступными без авторизации.

## Задачи

### Auth API

- Реализовать `POST /api/auth/login`.
- Реализовать `GET /api/auth/me`.
- Описать request/response DTO:
  - `LoginRequest`
  - `LoginResponse`
  - `CurrentUserResponse`
- Для успешного входа возвращать:
  - `accessToken`
  - `expiresAt`
  - объект пользователя.

### Проверка пароля

- Использовать безопасное хеширование пароля.
- Не сравнивать пароль в открытом виде.
- При неверном логине или пароле возвращать `401 Unauthorized`.
- Не раскрывать, какое именно поле неверное.

### JWT

- Подключить JWT Bearer authentication.
- Добавить настройки:
  - issuer;
  - audience;
  - secret/signing key;
  - lifetime.
- Добавить claims:
  - user id;
  - login.
- Проверить истечение токена.

### Защита admin API

- Подготовить общую схему защиты `/api/admin/*`.
- Проверить, что endpoint `GET /api/auth/me` работает только с валидным токеном.
- Подготовить основу для будущих admin controllers.

### Ошибки

- Возвращать единый формат `ErrorResponse`.
- Обработать:
  - некорректный request body;
  - неверные credentials;
  - отсутствие токена;
  - невалидный токен;
  - истекший токен.

## Результат спринта

- Администратор может авторизоваться.
- Backend выдает JWT access token.
- Защищенные endpoints требуют `Authorization: Bearer <token>`.
- Невалидные запросы получают корректные HTTP-статусы.

## Definition of Done

- `POST /api/auth/login` возвращает `200 OK` для валидных данных.
- `POST /api/auth/login` возвращает `401 Unauthorized` для неверных данных.
- `GET /api/auth/me` возвращает текущего пользователя с валидным токеном.
- `GET /api/auth/me` возвращает `401 Unauthorized` без токена.
- JWT secret не хранится в коде.
- Swagger позволяет тестировать авторизацию через Bearer token.

## Риски и решения

- Слишком долгий lifetime токена снижает безопасность. Для MVP можно использовать разумное значение и вынести его в конфигурацию.
- Хранение токена на frontend будет реализовано позже, но backend-контракт должен быть стабильным уже сейчас.
- Ошибки авторизации должны быть одинаковыми, чтобы не помогать подбору логина.

## Что не входит в спринт

- UI логина в админке.
- Refresh token.
- Ролевая модель.
- OAuth или внешние провайдеры.
- CRUD административных ресурсов.
