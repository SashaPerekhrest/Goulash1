# Спринт 03. PageContent API

## Цель

Реализовать API для получения и редактирования HTML-контента страницы "О себе".

После спринта публичный сайт сможет получить HTML страницы, а админка сможет прочитать и обновить этот контент через защищенный endpoint.

## Контекст

Страница "О себе" является главным входом в портфолио. Контент хранится в базе как HTML и редактируется через TinyMCE в административной панели.

## Задачи

### Публичный endpoint

- Реализовать `GET /api/pages/{key}`.
- Для ключа `about` возвращать:
  - `key`
  - `htmlContent`
  - `updatedAt`
- Если страница не найдена, возвращать `404 Not Found`.

### Административные endpoints

- Реализовать `GET /api/admin/pages/{key}`.
- Реализовать `PUT /api/admin/pages/{key}`.
- Защитить оба endpoint через JWT.
- В admin response возвращать:
  - `id`
  - `key`
  - `htmlContent`
  - `createdAt`
  - `updatedAt`

### DTO и валидация

- Создать DTO для публичного ответа.
- Создать DTO для административного ответа.
- Создать DTO для обновления:
  - `htmlContent`
- Проверить, что `htmlContent` не пустой.
- Ограничить максимальный размер HTML, если это принято в backend-политике.

### Работа с HTML

- Зафиксировать стратегию обработки HTML.
- Минимальный вариант для MVP:
  - хранить HTML как есть;
  - редактировать только через защищенную админку;
  - на frontend рендерить HTML осторожно.
- Более безопасный вариант:
  - добавить sanitizer на backend;
  - разрешить только безопасные теги и атрибуты.

### Ошибки

- `400 Bad Request` для невалидного HTML-контента.
- `401 Unauthorized` для admin endpoints без токена.
- `404 Not Found` для неизвестного ключа страницы, включая `PUT /api/admin/pages/{key}`.

## Результат спринта

- Контент страницы "О себе" доступен публично.
- Контент страницы "О себе" редактируется через защищенный endpoint.
- API-контракт соответствует документации.

## Definition of Done

- `GET /api/pages/about` возвращает публичный контент.
- `GET /api/admin/pages/about` требует авторизацию.
- `PUT /api/admin/pages/about` обновляет HTML.
- После обновления публичный endpoint возвращает новый HTML.
- Ошибки возвращаются в едином формате.
- Swagger содержит новые endpoints.

## Риски и решения

- HTML-контент связан с XSS-рисками. Нужно явно зафиксировать выбранную стратегию и не забыть вернуться к ней перед финальной сдачей.
- Если страница `about` отсутствует в базе, seed должен ее создать или API должен корректно отвечать `404`.
- TinyMCE может генерировать HTML с inline-стилями. Нужно заранее решить, разрешены ли они.

## Что не входит в спринт

- UI TinyMCE в админке.
- Публичная страница Next.js.
- Управление проектами.
- Загрузка изображений.
