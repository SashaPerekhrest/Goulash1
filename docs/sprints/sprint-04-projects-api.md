# Спринт 04. Projects API

## Цель

Реализовать полный backend API для проектов без обязательной интеграции с файловым хранилищем.

После спринта проекты можно создавать, редактировать, удалять и получать как через публичные, так и через административные endpoints. Поле `imageUrl` на этом этапе можно задавать вручную.

## Контекст

Проекты являются основным содержанием портфолио. Они делятся на две категории: `AI` и `OTHER`. Публичная часть показывает только опубликованные проекты, а админка работает и с черновиками.

## Задачи

### Публичные endpoints

- Реализовать `GET /api/projects`.
- Поддержать query parameter `category`.
- Если `category` передан, фильтровать по `AI` или `OTHER`.
- Возвращать только проекты с `isPublished = true`.
- Реализовать `GET /api/projects/{slug}`.
- Для detail endpoint возвращать только опубликованный проект.
- Если проект не найден или не опубликован, возвращать `404 Not Found`.

### Административные endpoints

- Реализовать `GET /api/admin/projects`.
- Поддержать query parameter `category`.
- Возвращать опубликованные и неопубликованные проекты.
- Реализовать `GET /api/admin/projects/{id}`.
- Реализовать `POST /api/admin/projects`.
- Реализовать `PUT /api/admin/projects/{id}`.
- Реализовать `DELETE /api/admin/projects/{id}`.
- Защитить все admin endpoints через JWT.

### DTO

- Создать DTO для project list item.
- Создать DTO для project detail.
- Создать DTO для create request.
- Создать DTO для update request.
- Не дублировать лишние модели без необходимости, но сохранить ясность публичного и административного контрактов.

### Валидация

- `title` обязателен, максимум 200 символов.
- `slug` обязателен, максимум 200 символов.
- `slug` содержит только латиницу, цифры и дефисы.
- `shortDescription` обязателен, максимум 500 символов.
- `imageUrl` необязателен, максимум 1000 символов.
- Если `imageUrl` не задан, публичный сайт и админка должны показывать аккуратное fallback-состояние.
- `htmlContent` обязателен.
- `category` обязателен и принимает только `AI` или `OTHER`.
- `isPublished` обязателен.

### Slug conflict

- При создании проекта проверять уникальность `slug`.
- При обновлении проекта проверять, что новый `slug` не занят другим проектом.
- Возвращать `409 Conflict` при конфликте.

### Сортировка

- Зафиксировать порядок выдачи проектов.
- Рекомендуемый вариант:
  - новые выше старых;
  - сортировка по `createdAt desc`.

## Результат спринта

- Backend поддерживает полный CRUD проектов.
- Публичные endpoints показывают только опубликованные проекты.
- Административные endpoints показывают все проекты.
- Контракты соответствуют документации.

## Definition of Done

- `GET /api/projects?category=AI` возвращает только опубликованные AI-проекты.
- `GET /api/projects?category=OTHER` возвращает только опубликованные OTHER-проекты.
- `GET /api/projects/{slug}` возвращает 404 для черновика.
- Admin CRUD работает с валидным JWT.
- Создание проекта с занятым slug возвращает `409 Conflict`.
- Невалидные данные возвращают `400 Bad Request`.
- Удаление существующего проекта возвращает `204 No Content`.

## Риски и решения

- Публичный detail endpoint не должен раскрывать черновики.
- Категория должна совпадать с API-контрактом по регистру: `AI`, `OTHER`.
- При удалении проекта на этом этапе файл изображения еще не удаляется из хранилища, потому что интеграция с файлами будет позже.

## Что не входит в спринт

- Фактическая загрузка файлов.
- UI списков проектов.
- UI формы проекта.
- SEO страницы проекта.
