# Спринт 11. Полировка, безопасность и сдача

## Цель

Довести проект до демонстрационного состояния: проверить безопасность, UX, адаптивность, документацию, сборку и основные пользовательские сценарии.

После спринта проект должен быть готов к показу как тестовое задание.

## Контекст

К этому моменту функциональность уже реализована. Основная задача - убрать шероховатости, закрыть очевидные риски и подготовить понятную сдачу.

## Задачи

### Security pass

- Проверить, что административные endpoints закрыты авторизацией.
- Проверить, что публичные endpoints не раскрывают черновики.
- Проверить, что пароль администратора хранится хешем.
- Проверить, что JWT secret не лежит в репозитории.
- Проверить CORS origins.
- Проверить ограничения загрузки файлов.
- Вернуться к HTML/XSS стратегии:
  - sanitizer;
  - whitelist;
  - осознанный MVP trade-off с описанием риска.
- Проверить SVG upload, если он разрешен.

### UX pass public-web

- Проверить главную страницу.
- Проверить списки проектов.
- Проверить пустые состояния.
- Проверить детальную страницу проекта.
- Проверить 404 для отсутствующего проекта.
- Проверить адаптивность:
  - desktop;
  - tablet;
  - mobile.
- Проверить длинные названия, длинные descriptions и отсутствие визуальных поломок.

### UX pass admin-web

- Проверить login flow.
- Проверить logout.
- Проверить истекший или удаленный token.
- Проверить редактирование "О себе".
- Проверить создание проекта.
- Проверить редактирование проекта.
- Проверить удаление проекта.
- Проверить upload изображения.
- Проверить отображение ошибок backend validation.

### SEO pass

- Проверить title и description для:
  - `/`;
  - `/ai-projects`;
  - `/other-projects`;
  - `/projects/[slug]`.
- Проверить человекочитаемые URL.
- Проверить, что страницы проектов не требуют client-only rendering для базового контента.

### Тестирование

- Добавить backend-тесты на критичную логику, если позволяет время:
  - auth;
  - project validation;
  - public filtering `isPublished`;
  - slug conflict.
- Добавить ручной smoke checklist для frontend.
- Проверить production build всех приложений.

### Документация

- Обновить README.
- Описать:
  - назначение проекта;
  - стек;
  - локальный запуск;
  - Docker Compose запуск;
  - env variables;
  - admin credentials для development;
  - основные маршруты;
  - Swagger URL.
- Добавить раздел "Известные ограничения", если остались компромиссы.

### Демо-данные

- Подготовить осмысленный контент страницы "О себе".
- Добавить несколько AI-проектов.
- Добавить несколько OTHER-проектов.
- Проверить, что опубликованные проекты выглядят убедительно на публичном сайте.

## Результат спринта

- Проект стабильно запускается.
- Основные сценарии проверены.
- Документация достаточна для ревьюера.
- Публичная часть выглядит как портфолио, а не как технический черновик.
- Админка позволяет управлять контентом без изменения кода.

## Definition of Done

- Backend build проходит.
- Public Web build проходит.
- Admin Web build проходит.
- Docker Compose окружение поднимается.
- Smoke сценарии проходят.
- Нет секретов в репозитории.
- README актуален.
- В проекте есть demo content.
- Известные ограничения явно описаны.

## Риски и решения

- Финальный спринт легко раздуть. Нужно фокусироваться на вещах, которые влияют на демонстрацию и требования ТЗ.
- Если полноценные автотесты не успевают, важен хотя бы четкий manual smoke checklist.
- Если есть security trade-off по HTML, лучше честно описать его и показать направление решения, чем оставить неявным.

## Что не входит в спринт

- Большие продуктовые фичи сверх ТЗ.
- Полноценная ролевая модель.
- CI/CD, если он не требуется для сдачи.
- Production Kubernetes/Cloud deployment.
