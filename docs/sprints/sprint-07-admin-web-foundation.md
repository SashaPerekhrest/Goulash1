# Спринт 07. Admin Web foundation

## Цель

Реализовать основу административной панели: маршрутизацию, layout, авторизацию на frontend, API-клиент и защищенные страницы.

После спринта администратор должен иметь возможность войти в админку и попасть в закрытый интерфейс.

## Контекст

Админка работает как отдельное Vite-приложение и в локальной разработке доступна по адресу `http://localhost:5173/admin`. Она будет использовать backend API и JWT token.

## Задачи

### Библиотеки

- Подключить MUI.
- Подключить React Router.
- Подключить TanStack Query.
- Подключить React Hook Form.
- Подготовить место для TinyMCE, но сам редактор можно внедрить в следующем спринте.

### Routing

- Настроить базовый router.
- Добавить маршруты:
  - `/admin/login`
  - `/admin/about`
  - `/admin/ai-projects`
  - `/admin/other-projects`
- Настроить redirect с `/admin` на подходящий раздел:
  - если пользователь не авторизован, на `/admin/login`;
  - если авторизован, на `/admin/about`.

### Auth UI

- Создать страницу логина.
- Поля:
  - login;
  - password.
- Добавить кнопку входа.
- Показывать ошибку при неверных данных.
- Блокировать повторную отправку во время запроса.

### Auth state

- Сохранять `accessToken`.
- Проверять текущего пользователя через `GET /api/auth/me`.
- При ошибке авторизации очищать token.
- Перенаправлять на `/admin/login`.

### API client

- Создать общий API-клиент.
- Настроить base URL через env.
- Автоматически добавлять `Authorization: Bearer <token>` для защищенных запросов.
- Обрабатывать `401 Unauthorized`.

### Protected routes

- Создать компонент или routing-обертку для защищенных страниц.
- Не показывать приватный UI до проверки auth state.
- При отсутствии токена перенаправлять на login.

### Admin layout

- Создать общий layout админки.
- Добавить навигацию:
  - "О себе";
  - "Проекты с ИИ";
  - "Другие проекты".
- Добавить logout.
- Добавить область основного контента.

## Результат спринта

- Админка запускается.
- Страница логина работает.
- JWT token используется для защищенных запросов.
- Приватные маршруты закрыты.
- Есть базовый layout и навигация.

## Definition of Done

- Неавторизованный пользователь при открытии `/admin` попадает на login.
- Валидные credentials приводят в админку.
- Невалидные credentials показывают ошибку.
- После logout пользователь возвращается на login.
- Запросы к защищенным страницам используют Bearer token.
- Сборка admin-web проходит без ошибок.

## Риски и решения

- Хранение token в localStorage удобно для MVP, но имеет security trade-offs. Нужно зафиксировать выбранный вариант.
- При истечении токена все защищенные запросы должны приводить к logout/redirect.
- Базовый path `/admin` в Vite нужно настроить так, чтобы локальный URL соответствовал ТЗ.

## Что не входит в спринт

- Редактирование страницы "О себе".
- CRUD проектов.
- Загрузка файлов.
- TinyMCE integration.
