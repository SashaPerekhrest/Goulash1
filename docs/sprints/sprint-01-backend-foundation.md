# Спринт 01. Backend foundation

## Цель

Собрать базовый backend-слой: доменные сущности, подключение PostgreSQL, EF Core, миграции, Swagger и стартовые данные.

После спринта backend должен уметь подключаться к базе, создавать схему данных и отдавать базовую техническую информацию через Swagger.

## Контекст

Backend является центром системы. С ним будут работать и публичный сайт, и административная панель. Поэтому сначала нужно стабилизировать модель данных и инфраструктуру API.

## Задачи

### Доменные сущности

- Создать сущность `AdminUser`:
  - `Id`
  - `Login`
  - `PasswordHash`
  - `CreatedAt`
  - `UpdatedAt`
- Создать сущность `PageContent`:
  - `Id`
  - `Key`
  - `HtmlContent`
  - `CreatedAt`
  - `UpdatedAt`
- Создать сущность `Project`:
  - `Id`
  - `Title`
  - `Slug`
  - `ShortDescription`
  - `ImageUrl`
  - `HtmlContent`
  - `Category`
  - `IsPublished`
  - `CreatedAt`
  - `UpdatedAt`
- Создать enum `ProjectCategory`:
  - `AI`
  - `OTHER`

### EF Core и PostgreSQL

- Подключить EF Core PostgreSQL provider.
- Создать `PortfolioDbContext`.
- Настроить таблицы:
  - `admin_users`
  - `page_contents`
  - `projects`
- Настроить ограничения:
  - уникальный `login` для `admin_users`;
  - уникальный `key` для `page_contents`;
  - уникальный `slug` для `projects`;
  - обязательные поля;
  - максимальные длины строк.
- Добавить первую миграцию.
- Проверить применение миграции к локальной базе.

### Seed данных

- Добавить начального администратора.
- Добавить страницу `about`.
- Значения логина/пароля администратора брать из конфигурации или development seed.
- Пароль не хранить в открытом виде.

### Конфигурация API

- Настроить чтение connection string из конфигурации.
- Добавить Swagger / OpenAPI.
- Настроить CORS для локальных frontend-приложений.
- Добавить базовый health endpoint, например `GET /health`.

## Результат спринта

- Backend подключается к PostgreSQL.
- EF Core создает необходимые таблицы.
- В базе есть начальные данные.
- Swagger доступен локально.
- Есть базовая инфраструктура для будущих API.

## Definition of Done

- `dotnet build` проходит без ошибок.
- Миграции применяются на чистую PostgreSQL базу.
- В Swagger виден хотя бы health endpoint.
- Таблицы соответствуют документации.
- Seed не создает дубликаты при повторном запуске.
- Пароль администратора хранится в виде хеша.

## Риски и решения

- Если seed администратора завязан на hardcoded пароль, нужно явно пометить это как development-only.
- Если enum хранится строкой, нужно проверить совместимость значений `AI` и `OTHER` с API-контрактом.
- Если миграции запускаются автоматически, нужно аккуратно ограничить это development-окружением или явно описать поведение.

## Что не входит в спринт

- JWT авторизация.
- CRUD проектов.
- PageContent API.
- Интеграция с SeaweedFS.
- Frontend-разработка.
