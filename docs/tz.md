# Техническое задание

## 1. Назначение проекта

Необходимо разработать публичный лендинг-портфолио с административной панелью для управления контентом.

Проект создается в рамках тестового задания для вакансии "специалист по работе и внедрению ИИ". Лендинг должен не просто дублировать резюме, а показывать релевантность опыта кандидата вакансии: опыт работы с ИИ, внедрение решений, разработку проектов, работу с backend/frontend, интеграциями, данными и автоматизацией.

Сайт должен состоять из публичной части и закрытой административной панели.

## 2. Цели проекта

Основные цели:

- представить кандидата как специалиста, способного работать с ИИ-решениями и внедрять их в реальные процессы;
- показать проекты, связанные с искусственным интеллектом;
- отдельно показать другие проекты, подтверждающие общий инженерный опыт;
- дать возможность управлять контентом сайта без изменения кода;
- продемонстрировать владение современным стеком: .NET, PostgreSQL, React, Next.js, SeaweedFS, TinyMCE, Docker.

## 3. Пользовательские роли

### 3.1. Посетитель сайта

Посетитель может:

- открыть публичный лендинг;
- просмотреть страницу "О себе";
- просмотреть список проектов с ИИ;
- просмотреть список других проектов;
- открыть детальную страницу любого проекта.

Посетитель не имеет доступа к административной панели.

### 3.2. Администратор

Администратор может:

- авторизоваться в административной панели;
- редактировать HTML-контент страницы "О себе";
- создавать проекты;
- редактировать проекты;
- удалять проекты;
- загружать изображение для карточки проекта при необходимости;
- задавать полное HTML-описание проекта через редактор TinyMCE.

## 4. Публичная часть сайта

Публичная часть должна быть реализована на Next.js с поддержкой SEO.

### 4.1. Общий layout

На всех публичных страницах должны быть:

- верхняя шапка с навигацией;
- основная область контента;
- нижний футер.

Навигация в шапке:

- "О себе";
- "Проекты с ИИ";
- "Другие проекты".

Футер:

```text
2026
```

### 4.2. Страница "О себе"

Маршрут:

```text
/
```

Страница отображает HTML-контент, который администратор задает через TinyMCE в административной панели.

Контент может включать:

- краткое описание кандидата;
- опыт работы;
- ключевые навыки;
- опыт работы с ИИ;
- подход к внедрению ИИ-решений;
- технологии;
- ссылки на контакты, резюме, GitHub или другие ресурсы.

Требования:

- HTML-контент должен корректно отображаться на странице;
- страница должна быть адаптивной;
- для страницы должны быть заданы SEO title и description.

### 4.3. Страница "Проекты с ИИ"

Маршрут:

```text
/ai-projects
```

Страница отображает список проектов категории `AI`.

Каждый проект отображается в виде карточки:

- слева небольшое изображение или логотип проекта, если `imageUrl` задан;
- если изображение не задано, карточка должна отображаться с аккуратным fallback-состоянием без поломки layout;
- справа название проекта жирным шрифтом;
- под названием краткое описание;
- вся карточка кликабельна.

При нажатии на карточку пользователь переходит на страницу проекта.

Требования:

- список проектов должен загружаться из backend API;
- отображаются только опубликованные проекты категории `AI`;
- карточки должны быть адаптивными;
- при отсутствии проектов нужно показать аккуратное пустое состояние.

### 4.4. Страница "Другие проекты"

Маршрут:

```text
/other-projects
```

Страница отображает список проектов категории `OTHER`.

Логика карточек такая же, как на странице "Проекты с ИИ".

Требования:

- список проектов должен загружаться из backend API;
- отображаются только опубликованные проекты категории `OTHER`;
- карточки должны вести на детальную страницу проекта.

### 4.5. Страница проекта

Маршрут:

```text
/projects/[slug]
```

Страница отображает полное описание проекта.

Данные проекта:

- название;
- изображение, если оно задано;
- краткое описание;
- полный HTML-контент;
- категория проекта.

Полное описание проекта хранится в базе данных как HTML и редактируется через TinyMCE.

Требования:

- страница должна находить проект по `slug`;
- если проект не найден или не опубликован, должна отображаться страница 404;
- HTML-контент должен корректно рендериться;
- для каждого проекта должны формироваться SEO title и description на основе данных проекта.

## 5. Административная панель

Административная панель должна быть реализована на React + Vite + TypeScript.

Адрес:

```text
/admin
```

В локальной разработке админка запускается как отдельное Vite-приложение и доступна по адресу `http://localhost:5173/admin`. В production маршрут `/admin` должен быть настроен через reverse proxy или routing frontend-инфраструктуры.

Админка представляет собой небольшую CRM для управления контентом публичного сайта.

### 5.1. Авторизация

При переходе в админку неавторизованный пользователь должен попадать на страницу входа.

Форма входа:

- логин;
- пароль;
- кнопка входа;
- отображение ошибки при неверных данных.

После успешного входа пользователь получает доступ к административному интерфейсу.

Требования:

- административные API должны быть защищены;
- пароль должен храниться в виде хеша;
- токен авторизации должен использоваться для запросов к защищенным API;
- при истечении сессии пользователь должен быть перенаправлен на страницу входа.

### 5.2. Layout админки

Внутри админки должны быть:

- боковое или верхнее меню;
- страницы управления;
- область основного контента.

Разделы админки:

- "О себе";
- "Проекты с ИИ";
- "Другие проекты".

### 5.3. Админ-страница "О себе"

Страница содержит HTML-редактор TinyMCE.

Функции:

- загрузка текущего HTML-контента страницы "О себе";
- редактирование HTML;
- сохранение изменений.

После сохранения новый HTML должен отображаться на публичной странице "О себе".

### 5.4. Админ-страница "Проекты с ИИ"

Страница содержит таблицу проектов категории `AI`.

Колонки таблицы:

- название;
- краткое описание;
- статус публикации;
- действия.

Действия:

- редактировать;
- удалить.

Сверху таблицы должна быть кнопка "Создать".

При создании или редактировании открывается модальное окно шириной около 90% экрана.

Поля формы проекта:

- название;
- slug;
- изображение для карточки, необязательное поле;
- краткое описание;
- полный HTML-контент через TinyMCE;
- статус публикации.

Функции:

- создание проекта;
- редактирование проекта;
- удаление проекта;
- загрузка изображения в SeaweedFS при необходимости;
- сохранение ссылки на изображение в базе данных, если изображение загружено;
- управление статусом публикации проекта.

### 5.5. Админ-страница "Другие проекты"

Страница аналогична разделу "Проекты с ИИ", но работает с категорией `OTHER`.

Функции:

- отображение таблицы проектов категории `OTHER`;
- создание проекта;
- редактирование проекта;
- удаление проекта;
- загрузка изображения;
- редактирование полного HTML-контента проекта.
- управление статусом публикации проекта.

## 6. Технологический стек

### 6.1. Backend

- .NET 8;
- ASP.NET Core Web API;
- Entity Framework Core;
- PostgreSQL;
- Swagger / OpenAPI;
- JWT Bearer авторизация;
- интеграция с S3-compatible хранилищем SeaweedFS.

### 6.2. Публичный сайт

- Next.js;
- React;
- TypeScript;
- SEO через metadata API Next.js;
- адаптивная верстка.

### 6.3. Административная панель

- React;
- Vite;
- TypeScript;
- MUI;
- React Router;
- TanStack Query;
- React Hook Form;
- TinyMCE.

### 6.4. База данных

- PostgreSQL.

### 6.5. Файловое хранилище

- SeaweedFS.

SeaweedFS используется как S3-compatible хранилище для:

- изображений карточек проектов;
- изображений, загружаемых через админку;
- файлов, которые могут понадобиться для контента.

Для локальной разработки SeaweedFS поднимается в Docker Compose как сервис `seaweedfs` и предоставляет S3 endpoint на порту `8333`.

Backend должен сохранять в базе данных URL изображения, пригодный для отображения на публичном сайте. В локальной разработке это может быть прямой URL SeaweedFS, а в production - публичный домен хранилища, CDN или backend proxy URL.

### 6.6. Инфраструктура

- Docker;
- Docker Compose.

Через Docker Compose должны подниматься:

- backend API;
- PostgreSQL;
- SeaweedFS;
- публичный Next.js сайт;
- React-админка.

## 7. Основные сущности

### 7.1. PageContent

Сущность для хранения HTML-контента страниц.

Поля:

- `id`;
- `key`;
- `htmlContent`;
- `createdAt`;
- `updatedAt`.

Для страницы "О себе" используется ключ:

```text
about
```

### 7.2. Project

Сущность проекта.

Поля:

- `id`;
- `title`;
- `slug`;
- `shortDescription`;
- `imageUrl`;
- `htmlContent`;
- `category`;
- `isPublished`;
- `createdAt`;
- `updatedAt`.

Возможные значения `category`:

- `AI`;
- `OTHER`.

### 7.3. AdminUser

Сущность администратора.

Поля:

- `id`;
- `login`;
- `passwordHash`;
- `createdAt`;
- `updatedAt`.

## 8. Нефункциональные требования

### 8.1. SEO

Публичная часть должна:

- иметь человекочитаемые URL;
- иметь title и description для основных страниц;
- иметь title и description для страниц проектов;
- корректно отдавать HTML для индексации.

### 8.2. Безопасность

Требования:

- административная панель закрыта авторизацией;
- административные API защищены;
- пароли не хранятся в открытом виде;
- HTML-контент должен быть обработан с учетом XSS-рисков;
- загрузка файлов должна ограничивать типы и размер файлов.

### 8.3. Производительность

Требования:

- публичные страницы должны быстро загружаться;
- изображения должны отображаться в оптимальном размере;
- запросы к API должны быть минимально необходимыми;
- списки проектов должны быть доступны без заметной задержки.

### 8.4. Адаптивность

Сайт и админка должны корректно отображаться:

- на desktop;
- на tablet;
- на mobile.

## 9. Ожидаемый результат

В результате должен быть готов проект, содержащий:

- публичный сайт-портфолио;
- административную панель;
- backend API;
- базу данных PostgreSQL;
- S3-compatible файловое хранилище SeaweedFS;
- документацию;
- инструкции по запуску;
- инструкции по локальному открытию лендинга;
- ссылку на опубликованный лендинг, если внешний деплой входит в формат сдачи;
- ссылку на репозиторий.
